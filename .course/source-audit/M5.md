4. Se conservan los tests heredados de M4 y M5 amplía la suite hasta **14 clases de test / 32 métodos `@Test`** en el snapshot final.

## Corrección de portabilidad de la continuidad M4 → M5

El validador de continuidad compara contenido lógico normalizando únicamente
finales de línea CRLF/LF en artefactos textuales. Esto evita falsos `PRESERVED`
en Windows cuando Git materializa M4 con CRLF (`core.autocrlf`) mientras el
payload M5 conserva LF. La normalización no oculta cambios de contenido:
`MODIFIED` sigue exigiendo una diferencia real tras normalizar EOL.

## Corrección del gate runtime CORS

Durante la ejecución real en Windows, Spring MVC 6.2 devolvió correctamente
`403 Forbidden` para un `Origin` no autorizado (`http://localhost:9999`).
El validador runtime anterior esperaba erróneamente `200` sin cabecera CORS.
Se corrige el gate para exigir el comportamiento real y más estricto:
`403` y ausencia de `Access-Control-Allow-Origin`.

No cambia el proyecto del alumno, la teoría, la práctica ni los PDFs; cambia
únicamente la expectativa del gate automático de runtime.

## Corrección R2 del gate runtime en CI

La primera ejecución de `Validar M5` sobre el commit
`d5f3a8cb36d210fcdb63bffcb45ed8b8cd2a51a8` confirmó que trazabilidad,
mutation gate, Maven, 32 tests, Checkstyle, Javadoc y package pasaban, pero el
gate runtime leyó `/api/v1/alumnos` demasiado pronto y observó temporalmente
`0` filas.

La causa es una carrera de arranque: el servidor embebido puede aceptar
peticiones HTTP antes de que finalice el `CommandLineRunner` de
`DatosInicialesConfig`, que inserta los dos alumnos del perfil `dev`.

R2 no relaja el requisito. El gate sigue exigiendo exactamente dos alumnos,
`totalElements=2` y `totalPages=1`, pero espera de forma acotada hasta 20 s
(sondeo cada 250 ms) a que termine la inicialización. Si los datos no aparecen,
la validación sigue fallando.
