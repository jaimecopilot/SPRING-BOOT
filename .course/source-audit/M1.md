## 5. Matriz maestra de los 58 pasos

Convenciones:

- `VERIFY`: observar/probar sin cambio persistente.
- `CREATE`: nace un artefacto o símbolo permanente.
- `MODIFY`: evolución permanente.
- `TEMP MODIFY`: cambio deliberadamente temporal.
- `RESTORE/DELETE`: cierre obligatorio del estado temporal.

## 6. Correcciones editoriales/ técnicas obligatorias detectadas antes de redactar

Estas correcciones preservan la intención de la fuente, pero evitan enseñar afirmaciones contradictorias o ejercicios no reproducibles.

1. **1.1.10 - exclusión de Jackson.** La fuente propone probar un endpoint JSON que todavía no existe de forma estable. La edición nueva hará el probe JSON de forma temporal dentro del propio paso y lo restaurará. No quedará comportamiento extra escondido.
2. **1.2 - cuerpos de error.** Se validarán de forma fuerte código HTTP y propiedades estables. Campos concretos del JSON de error sólo se afirmarán si Spring Boot 3.5.16 los devuelve realmente con la configuración del curso.
3. **1.3 - constructor vacío.** Se explicará como la estrategia usada por nuestros DTOs y una forma simple de deserialización, no como una ley universal de Jackson.
4. **1.3 - campos desconocidos.** Se atribuirá el comportamiento al `ObjectMapper` auto-configurado por Spring Boot en esta baseline, evitando afirmar que es el default universal de cualquier Jackson puro.
5. **1.4 vs 1.5.** La fuente dice en 1.4 que PUT/PATCH/DELETE se harán en M3, pero 1.5 los implementa inmediatamente. La edición nueva dirá: se completan de forma introductoria en 1.5 y se profundizan/refactorizan en módulos posteriores.
6. **Número de endpoints.** Al finalizar 1.5 hay seis combinaciones método/ruta principales (dos GET + POST + PUT + PATCH + DELETE), no “cinco endpoints” si se cuentan operaciones.
7. **Generación de ID con `size()+1`.** Puede colisionar después de borrados. Se puede conservar como simplificación explícita del almacenamiento en memoria sólo si la guía declara la limitación; no se presentará como estrategia real de producción.
8. **PATCH con `Map<String,Object>`.** Es una simplificación pedagógica. Debe explicarse su fragilidad de tipos y limitarse a campos concretos; no se venderá como diseño final.
9. **Ordenación de 1.5.12.** El texto histórico llama opcional a `sort` pero usa `defaultValue="nombre"`, lo que ordena incluso sin parámetro. La edición nueva hará `sort` realmente opcional para que “sin ordenación” sea cierto.
10. **Estado real de M0.** La referencia histórica E1 recrea `SaludoController`; la edición nueva no lo hará porque M0 aprobado ya contiene `SaludoController`, `/hola`, `/adios` y sus tests. M1 los hereda.
