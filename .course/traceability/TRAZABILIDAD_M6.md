- Módulo: `M6 — Spring Security y JWT`.

- Fuente: páginas 1203–1550 (348 páginas).

- Artefacto funcional temporal: `InMemoryUserConfig.java`, `CREATE` en 6.2.4 y `DELETE` en 6.3.6; debe estar ausente del snapshot final.
- No se usa GitHub Actions: los gates se ejecutan localmente desde el BAT antes del único commit/push.

## 2. Qué garantiza la trazabilidad

**Dirección directa**: `PDF fuente → teoría → paso PRACTICA → acción → fichero/símbolo → hash final/estado → comando → observable → verificación`.

**Dirección inversa**: `fichero final → clasificación/origen → SHA/blob → paso(s) PRACTICA → concepto(s) teóricos → página fuente`. Los ficheros M5 preservados vuelven al blob M5 original; los ficheros nuevos o evolucionados deben volver a un paso docente concreto.

La validación no acepta un fichero funcional nuevo/evolucionado sin `step_refs`, una relación cuyo hash no coincide, un artefacto temporal que quede vivo, ni una relación inversa que no exista también en la dirección paso→fichero.
